## Why

导演部需要一套**多席位智能体集群**：约 100 个席位各自拥有独立 Agent 运行时，遵循业务关系与席位角色自主完成任务、彼此协同、空闲时主动推送信息；多套候选方案送入多套仿真系统推演择优后再下发执行，人类只做监督审核、尽量少干预。

当前工作区仅有参考项目 `deepseek-harness`（用于对齐前端客户端架构与界面结构），**尚无平台实现**。本次变更从零建立该平台，并以配置驱动、可插拔、每项能力带可执行断言为硬性约束，避免后续扩席位或换仿真系统时改动代码。

## What Changes

- **组织模型**：席位（约 100 个，配置驱动横向扩展，无硬编码上限）、角色（层级 `level`／密级 `clearance`／可分派权／可审批权）、席位间通过 `parent` 构成指挥链；活动（Activity）作为一等公民，切换活动即切换业务作用域，活动含准备／方案拟制／推演验证／执行／复盘五个阶段。
- **席位 Agent 运行时**：每个席位一个独立运行时；人格外置为 Markdown 文件（覆盖优先级 席位级 > 角色级 > 内置默认），业务人员改文件即可、不改代码；三层记忆（工作记忆／长期记忆／情景记忆）支持 `persist()`／`restore()`，集群重建后可召回。
- **带权限知识库**：公共知识库按角色密级差异化可见；**必须检索前过滤**（先按密级与角色白名单剔除不可见文档，再在可见集内检索），禁止"先检索再过滤"以免命中即泄漏；`deny` 优先级高于 `allow`。
- **Skill 体系**：采用 `SKILL.md` 开放标准（agentskills.io）；两层职责分离——技能本体在 `skills/<名称>/SKILL.md`（业务人员维护），编排配置在 `config/skills.yaml`（管理员维护谁能用／是否启用／如何打包）；三种可叠加组合方式：启停开关、角色授权、技能包 `packs`；提供 zip 上传安装入口，自动解析并登记，且带上传安全边界防护。
- **多席位协同**：群聊、席位直达会话、`@` 提及、指挥链广播；消息区分类型（指令／汇报／主动提示／待审产出）；支持从任意消息分支出新会话以做多方案分叉推演。
- **任务与人在回路**：任务按能力与负载自动分派、按 Skill 与密级筛选可用席位；无 `can_dispatch` 权限分派任务直接抛 `PermissionDenied`，无 `can_approve` 权限不能审批；产出状态机 `执行中 → 待审(WAITING_APPROVAL) → 人确认 → 完成`；人类反馈（Good/Bad response）被记录并作为自进化输入。
- **方案推演与仿真验证（MCP）**：多套候选方案由多个席位**并发**生成；每套方案送**多套仿真系统**推演；仿真系统经 MCP（JSON-RPC 2.0 over stdio）接入——引擎只需实现 MCP 服务端并在配置中登记启动命令与工具名即可接入，无需改代码；单个仿真系统连接失败不中断整体，仅标记为未连接；各结果按权重加权汇总、择优排序并输出对比报告；择优方案需人类确认后才下发。
- **Agent 自迭代／自进化**：闭环 反思 → 提炼 → 验证 → 固化；**禁止自动提权**，自进化产物强制 `clearance=1`，校验危险指令，全过程留痕可回滚；只进化规程不进化权限；产物写入 `runtime/` 独立目录，与手写技能库隔离、不污染版本控制。
- **前端控制台**：承载 11 个功能模块（活动选择与切换、会话列表、席位集群视图、协同消息流、人工审核队列、方案推演结果对比、知识库权限视图、Skill 管理入口、MCP 服务管理入口、执行轨迹视图、运行时指标），界面结构对齐 `deepseek-harness` 的客户端模块架构。
- **横切约束**：并发调度（总耗时约等于最慢单席，而非席位之和）、配置驱动、记忆持久化、可插拔集成、每项能力配套可执行断言。

## Capabilities

### New Capabilities

- `seats-and-roles`：席位、角色、指挥链与活动作用域的组织模型，配置驱动且可横向扩展
- `agent-runtime`：席位 Agent 运行时的构成（人格外置、三层记忆、权限边界）与空闲主动推送行为
- `knowledge-base`：带权限控制的公共知识库，检索前过滤与密级／角色可见性差异
- `skill-system`：SKILL.md 技能体系，本体与编排分离、三种组合方式、zip 上传安装及其安全边界
- `seat-collaboration`：多席位协同消息与会话（群聊／直达／@／广播／分支会话）及消息类型
- `task-and-approval`：任务分派、权限校验、产出状态机、人在回路审批与反馈记录
- `simulation-mcp`：多方案并发生成与多套仿真系统经 MCP 接入推演、加权择优与失败隔离
- `agent-evolution`：自进化闭环、禁止自动提权、留痕可回滚与产物隔离
- `web-console`：前端控制台承载的 11 个功能模块

### Modified Capabilities

（无 —— 本变更为全新项目建设，不存在既有能力规格需要变更）

## Impact

- **新建项目源码**于工作区根目录；`deepseek-harness/` 保留为前端客户端架构与界面结构的**参考**，不作为运行时依赖引入。
- **新增目录**：`config/`（`seats.yaml`、`skills.yaml`、`simulators.yaml` 等）、`skills/`（技能本体）、`runtime/`（自进化产物与运行时状态，与 `skills/` 隔离）。
- **新增依赖**：YAML 解析、MCP 客户端（JSON-RPC 2.0 over stdio）、zip 安全解压、前端构建链（Vite + React + TypeScript）；生产化阶段可替换为 RAGFlow/WeKnora 知识库、Redis Streams/Kafka 消息总线。
- **验证方式**：每项能力配套可复跑的测试脚本作为可执行断言；修改配置后需跑回归测试确认既有能力未被破坏。
- **范围排除**：前端视觉与交互设计（配色／布局／组件规范／动画／响应式）、具体军事战术与武器操作、涉密内容；所有 Skill 内容限定为公开方法论与流程框架。
