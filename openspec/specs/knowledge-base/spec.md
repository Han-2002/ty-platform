# knowledge-base Specification

## Purpose
提供按角色密级差异化可见的公共知识库，并在检索真正发生之前完成可见性过滤，防止不可见内容被命中即泄露。

## Requirements

### Requirement: 检索前按密级与角色白名单过滤

系统 SHALL 在检索执行前，先依据请求方角色的密级与角色白名单剔除不可见文档，再在剩余可见集合内执行检索；系统 MUST NOT 采用先检索再过滤的方式。

#### Scenario: 越权文档不参与检索且不出现在结果中

- **WHEN** 密级较低的角色检索一个关键词，而该关键词仅命中一篇超出其密级的文档
- **THEN** 检索结果 MUST 为空，且返回的匹配计数、摘要、片段等任何字段 MUST NOT 暴露该文档的存在或内容

#### Scenario: 可见集内检索结果正确返回

- **WHEN** 某角色检索的关键词命中其可见范围内的一篇文档
- **THEN** 该文档 MUST 正常出现在检索结果中，且内容与权限无关地被完整返回

### Requirement: deny 优先级高于 allow

系统 SHALL 保证在知识库可见性判定中，`deny` 规则的优先级 MUST 高于 `allow` 规则；当同一文档同时被 `deny` 与 `allow` 命中时，该文档 MUST 不可见。

#### Scenario: 同时命中 deny 与 allow 时不可见

- **WHEN** 某文档的访问控制同时匹配到一条 `deny` 规则与一条 `allow` 规则
- **THEN** 该文档 MUST 对请求方不可见，且不参与检索

### Requirement: 同一知识库对不同角色呈现不同可见条数

系统 SHALL 使同一份知识库对不同角色呈现不同的可见文档数量，可见条数 MUST 严格由角色权限决定。

#### Scenario: 不同角色查询同一知识库得到不同条数

- **WHEN** 知识库共含 5 篇文档，分别由总导演、参谋、保障三个角色查询全部可见文档
- **THEN** 总导演 MUST 可见 5 条、参谋 MUST 可见 4 条、保障 MUST 可见 2 条，且每个角色返回的文档集合 MUST 是其权限范围内的完整集合
